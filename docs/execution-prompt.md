# Prompt para executar no projeto

Copie o texto abaixo para uma sessão na raiz de ~/projects/adlermedrado.com.br, após extrair o pacote.

---

Implemente o redesign do meu site Hugo conforme os documentos em docs/.

Leia primeiro os AGENTS.md aplicáveis. Depois leia docs/README.md, docs/analysis.md, docs/design.md, docs/spec.md, docs/roadmap.md e docs/acceptance.md. Abra os PNGs selecionados em design.md, usando ferramenta visual quando disponível. Os HTMLs do Stitch servem de referência para tradução à stack existente.

Siga as etapas R0 a R4. Comece inspecionando o projeto real e identificando caminhos, comandos de build, representação de idiomas, assets e assinatura. Esses detalhes não foram confirmados na preparação. Registre o mapeamento e continue a implementação com base no checkout.

Use home_adler_medrado para desktop escuro, home_light_parchment_adler_medrado_1 para desktop claro, home_mobile_adler_medrado_1 para mobile escuro e home_mobile_adler_medrado_2 para mobile claro. A pasta home_light_parchment_adler_medrado_2 contém uma tela escura apesar do nome. O menu dedicado orienta a lista vertical e a moldura, com posição adaptada para uso em telas baixas.

Entregue a home completa, componentes compartilhados, dois temas funcionais, seletor EN/PT mobile, menu acessível e atalhos reais. Gere dados e links pelo Hugo. Confirme se idiomas são taxonomia antes de usar Page.Lang. Preserve os contratos de assinatura e outputs atuais. Use o asset de identidade do projeto e trate a ausência conforme spec.md.

Execute o trabalho em etapas pequenas, valide cada etapa e atualize os checkboxes de roadmap.md apenas quando concluídos. Resolva decisões reversíveis com base na especificação. Se algo estiver indisponível, registre a limitação e avance nas partes independentes. Preserve alterações minhas que já existirem no checkout.

Ao terminar, entregue resumo das mudanças, arquivos alterados, comandos exatos de preview/build, verificações e capturas disponíveis, além das pendências reais. O resultado deve ficar pronto para minha revisão local. Publicação, push e mudanças de infraestrutura ficam para uma solicitação posterior.
